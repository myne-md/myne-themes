# Contributing a theme

Thanks for dressing up Myne. This repo is the **community theme marketplace** —
a browse/share/install channel for Myne's custom themes. The per-client theme
*engine* already ships in the [Myne](https://github.com/myne-md/myne) desktop
app; this repo is the *distribution* side.

A Myne theme is **not CSS** — it's a small, validated `.json` map of design
tokens → color values. That constraint is what keeps installing a stranger's
theme safe (see [Trust & safety](#trust--safety)).

## What a submission looks like

One theme = one folder = one pull request against `develop`:

```
themes/<your-theme-slug>/
├── theme.json     # the palette: { "--paper": "#…", "--ink-1": "#…", … }
└── meta.json      # { name, author, description, license, homepage? }
```

- `<your-theme-slug>` is lowercase, hyphenated, unique (e.g. `warm-paper`, `nord-ish`).
- `preview.png` is **generated by CI** from your `theme.json` — do **not** add
  your own screenshot (see [Previews](#previews)).
- Put **all** metadata in `meta.json`, never in `theme.json`: the validator
  rejects any human-readable string inside the palette file.

### `theme.json`

A flat JSON object mapping Myne design tokens to values. Every **required-core**
token must be present (the neutral `--paper*` ramp, the `--ink-*` text ramp, the
`--line-*` hairlines, the `--accent*` family, and the state colors
`--danger*/--warning*/--success*`). A dark theme should also set the optional
`--syntax-*` / `--label-*` families so code and labels read correctly.

**Allowed value shapes** (allowlist — everything else is rejected):

- hex: `#fff`, `#ffff`, `#a1b2c3`, `#a1b2c3d4`
- color functions: `rgb()` / `rgba()` / `hsl()` / `hsla()` (digits/`.`/`,`/`%`/`/`/space only)
- bare CSS color keywords: `red`, `transparent`, `currentColor` (letters only, ≤24)
- `<number><unit>`: `0`, `12px`, `0.5rem`, `100%`

Anything else — `url(...)`, `@import`, `expression(...)`, `javascript:`,
`calc(...)`, `var(...)`, comment/escape tricks — is **rejected**. This is a
security boundary, not a style guide (the WebView executes theme values as CSS).

### `meta.json`

```json
{
  "name": "Warm Paper",
  "author": "Your Name (or handle)",
  "description": "A soft, low-contrast light theme for long writing sessions.",
  "license": "CC-BY-4.0",
  "homepage": "https://example.com"
}
```

`license` is **`CC-BY-4.0` for an original theme** you authored (see
[`LICENSING.md`](LICENSING.md)). If you are **porting an existing color scheme**
(e.g. Dracula, Nord, Solarized), keep the scheme's **upstream license** (usually
`MIT`), set `author` to the **original creator**, add the `upstream` URL, and
optionally `port_by` yourself. `homepage` is optional. Validated against
[`schema/meta.schema.json`](schema/meta.schema.json) — a license outside the
allowed SPDX set fails CI (add it in the same PR if a port needs it).

## Validate locally first

Run the **exact** validator the Myne client runs (no reimplementation — it's the
`theme-validator` crate from the main repo):

```bash
# from a checkout of the main myne repo:
cargo run -p theme-validator --bin validate -- path/to/theme.json
# exit 0 = valid; exit 1 = prints the rich {kind, key?, line?} reason
```

CI runs this same binary on your PR, plus a WCAG **contrast** check and a
`meta.json` schema/license check.

## Submit

1. Fork, add your `themes/<slug>/` folder.
2. Confirm `theme.json` validates and reads well in the app (download → Settings →
   Appearance → Import).
3. Open a PR — **one theme per PR** — and complete the checklist + DCO line in the
   pull-request template.
4. A maintainer reviews for the things automation can't judge (see below) and merges.

## Trust & safety

The validator guarantees a theme can't **inject** anything — the worst a rejected
value does is fail to import. But a *valid* palette can still be **deceptive** or
**unreadable**, and automation only partly catches that:

- **Contrast** (unreadable text, `--ink` ≈ `--paper`) — caught by the CI contrast lint.
- **Semantic deception** (making `--danger` look green/safe, or `--success` look
  like a warning) — **caught by human review, not by CI.** Don't do this; it'll
  be rejected.

Themes are **validated on the user's device, never sandboxed** — we never claim a
theme is "safe", only that it passed validation. Review is a quality/deception
gate on top.

## Previews

The gallery preview is **rendered by CI from your `theme.json`** — a small mock-UI
styled with your palette. This makes the preview *authentic by construction* (it
can't misrepresent your theme) and means you never submit an image. Author
screenshots are not accepted.

## Governance & takedown

Merges are owned by CODEOWNERS. Deceptive, infringing, or malicious themes are
removed from the repo/gallery — see [`GOVERNANCE.md`](GOVERNANCE.md) and the
"report a theme" issue template. Note: because a download is a device-local copy,
removing a theme here stops offering it but does not uninstall existing copies.

By contributing you agree to the [Code of Conduct](CODE_OF_CONDUCT.md).

## Ornament (optional)

Beyond colour, a theme may select **ornament primitives** — generic visual parts
Myne draws, chosen per role rather than per element (`myne` repo
`docs/glossary.md`: *ornament primitive*, *ornament role*).

Three roles — `surface` (page and panel grounds), `box` (callouts, code blocks,
quotes, cards), `chrome` (tabs, buttons, bars).

**The matrix is sparse: 18 cells, not 24.** A role accepts only the primitives
that mean something for what it *is*. `chrome` is small, dense and repeated, so a
torn edge on it reads as damage rather than as style; `surface` is a sheet of
paper, so a ribbon belongs on the stationery sitting on it rather than on the
sheet. A key outside this table is **stored and ignored** — it validates, it
merges, it syncs, and it draws nothing, with no warning anywhere.

| Key | Values | `surface` | `box` | `chrome` |
|---|---|:--:|:--:|:--:|
| `--<role>-frame` | `none` `hairline` `thick` `double` `inset` | ● | ● | ● |
| `--<role>-shadow` | `none` `soft` `hard` `offset` | ● | ● | ● |
| `--<role>-texture` | `none` `paper` `grain` `scanline` `grid` | ● | ● | ● |
| `--<role>-ruled` | `none` `lines` `grid` `dotted` | ● | ● | — |
| `--<role>-edge` | `plain` `torn` `serrated` `cut` | ● | ● | — |
| `--<role>-fold` | `none` `folded` `dogear` | ● | ● | — |
| `--<role>-perforation` | `none` `left` `top` `both` | ● | ● | — |
| `--<role>-ribbon` | `none` `corner` `band` `label` | — | ● | — |
| `--tint` / `--tint-strength` | a colour, and a 0..1 strength | **not role-scoped** | | |

`theme-validator`'s `ROLE_PRIMITIVES` is the source of truth for this table; the
`—` cells are the ones it refuses.

Combinations are the point: thick frame + hard shadow + paper texture reads as a
polaroid; ruled ground + left perforation as a notebook page; grid texture +
hairline frame + no shadow as something technical.

Every key is **optional** — a colour-only theme is still a complete theme, and
the ten themes in this repo predate the vocabulary entirely. A value this
client does not recognize is not an error: CI warns, and the primitive renders
plain, so a theme may target a newer client without breaking on an older one.

Two notes on scope. **`frame` and `shadow` inherit into nested roles** (they are
set on the element itself), while the other six do not (they are set on the
decoration layer) — so if you frame `surface` and do not want the boxes inside it
framed, set the box frame to `none`. And **the tint wash is a single `--tint` /
`--tint-strength` pair**, not one per role: it is composed on the shared layer,
and its strength is capped in Myne's stylesheet so a wash can never bury text.

Two things ornament cannot do, by design: it never changes where anything sits
(it is paint, so a themed button is exactly where an unthemed one was), and the
strength of anything rendered *behind text* is capped in Myne's own stylesheet —
you cannot turn a texture up until the words disappear under it.

## Validate the gallery tooling

The Node tools have no npm dependencies; Node 22 is the only prerequisite.

```bash
npm test
for d in themes/*/; do node tools/lint-theme.mjs "$d"; done
node tools/build-index.mjs /tmp/themes-index.json
```

CI runs the same checks plus the client's `theme-validator` binary on every
theme and fixture. Do not commit the generated `index.json` or previews; the
website syncs them at build time.
